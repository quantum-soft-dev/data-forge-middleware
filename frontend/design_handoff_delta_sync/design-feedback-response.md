# Ответ дизайна на design-feedback.md — Delta Sync (022)

**Статус**: все пункты D1–D10 отработаны. Прототип (`prototype/Delta Sync.dc.html`) и `README.md` обновлены — этот бандл (v2) заменяет предыдущий целиком.

| # | Решение | Где отражено |
|---|---|---|
| D1 | Обновлено под целевую модель форматов: **Parquet — первичный пилл** (blue-50/blue, полный load таблицы), **CSV — вторичный legacy** (muted-пилл `#F5F5F4`/`#736F6D`, tooltip «Legacy · used by Bit BI»). Состояние «Parquet ещё не материализован» при живом CSV — некликабельный dashed-пилл «Parquet pending» (tooltip поясняет). Оба ключа null → прочерк. Ряд переживает полное исчезновение CSV без перевёрстки (flex-row с gap). Дельта-Parquet по сегментам в Checkpoints не смешивается. В прототипе: order_items/orders/payments — оба формата, customers — «Parquet pending» + CSV, products — только Parquet (пост-CSV мир), inventory — прочерк. | Прототип + README (Checkpoints) |
| D2 | Вариант 1 (рекомендация фидбэка): owner видит Segment throughput на основе «lite»-проекции сегментов (`recordCount` + `createdAt`, без seq-диапазонов и S3-ключей). Полная таблица сегментов остаётся admin-only. Макет не меняется; нужен бэкенд-эндпоинт lite-проекции + подтверждение продукта. | README (Activity) |
| D3 | Позиция дизайна: вариант 1 — утвердить Geist глобально (self-hosted, отдельная мини-задача). До решения продукта: все метрики макета допустимо применять на системном стеке без правок — вертикальные размеры заданы в px и от метрик шрифта не зависят. **Требует решения продукта.** | README (Global) |
| D4 | Каркас site detail зафиксирован: хлебная крошка «All sites» → заголовок (имя + чипы type / API / Active + подстрока) → табы. **Overview-таба нет**; первый таб — Upload history (существующий Batch List, отфильтрованный по сайту), второй — Delta Sync (только V2). Для V1-сайта остаётся один таб Upload history. Admin входит в тот же каркас из Admin-панели, отличается только `canManage`. В прототипе кликабельно: store-berlin-01 = V2-каркас, warehouse-legacy = V1-каркас. | Прототип (оба состояния) + README (IA) |
| D5 | Строка списка редизайнится в составе реальной: имя + бейджи Active / type / **API-чип** в одном кластере, вторая строка «Created … · Retention … days», health-пилл выровнен вправо в свободной зоне перед кнопками Deactivate / Delete. На узкой ширине пилл переносится под блок имени раньше кнопок. Пока bulk-данные health не загружены — ничего не рендерить (без пилла-скелетона). Состояние «нет sync-state» — серый пилл «No sync yet». | Прототип (Sites) + README (§3) |
| D6 | Принято. Подпись — «Sampled on each poll · since page open». Cold start (1–2 точки): плоская линия от первой точки, без placeholder-текста. «Last hour» откладывается до появления серверного time series (не MVP). | Прототип + README |
| D7 | Подтверждено: тосты — стандартный Sonner продукта; макетный тост — иллюстрация, не спецификация. Тексты остаются как в README. | README (Interactions) |
| D8 | Форматы зафиксированы: заголовок — «Batch #» + первые 8 символов UUID (`Batch #d3f8e0f1`); даты — продуктовый `formatDateTime` («Jul 05, 2026 09:14»), короткая форма «Jul 05, 12:41» для плотных ячеек (Recent segments); режим сессии — **два чипа**: «Delta session» (синий) + отдельный серый чип режима (CONTINUOUS / DELTA / FULL_SNAPSHOT) — снимает тавтологию «Delta session · DELTA». | Прототип + README |
| D9 | Доопределено: (a) empty state — весь таб заменяется одной центрированной карточкой «No sync activity yet» (иконка в blue-50 круге + подзаголовок), без sync-shell/Activity/Checkpoints/re-baseline — построено в прототипе (сценарий `empty`); (b) «Rebuild queued» живёт, пока серверный флаг `rebuildRequested` взведён, сбрасывается сервером по факту пересборки; (c) «Full snapshot scheduled» — от персистентного флага V35, после сброса кнопка re-baseline возвращается; (d) ошибки мутаций — Sonner error toast со стандартным текстом, без inline-блока; (e) >15 таблиц — таблица растёт + client-side фильтр по имени в шапке карточки, без пагинации. | Прототип + README |
| D10 | Исправлено: README теперь указывает Tailwind CSS 3.4. | README |
