# Data Forge Middleware (DFM) - AWS Infrastructure

## Обзор проекта
Проект представляет собой инфраструктуру AWS для развертывания бэкенда приложения Data Forge Middleware (DFM). Инфраструктура описывается как код (IaC) с использованием **AWS CloudFormation**.

Основная цель — создать автоматизированную, масштабируемую среду, включающую контейнеризированное приложение, базу данных, хранилище и сетевой слой.

## Архитектура

### Вычислительные ресурсы (Compute)
*   **ECS Fargate:** Запуск Docker-контейнеров бэкенда (`dfm-backend`). Используется модель serverless для упрощения управления.
*   **AWS Lambda:** Используется для автоматизации задач инициализации (Custom Resources), в частности для создания пользователей базы данных и выдачи прав.

### База данных и хранилище (Data)
*   **RDS PostgreSQL 17.7:** Основная реляционная база данных.
    *   *Dev Mode:* Включен `PubliclyAccessible: true` для прямого доступа разработчиков.
*   **S3 Bucket:** Хранилище для загружаемых файлов (`dfm-uploads`).
*   **Redis:** Используется для кэширования (параметры передаются в приложение).

### Сеть и безопасность (Network & Security)
*   **VPC:** Изолированная сетевая среда с публичными подсетями (в текущей Dev-конфигурации).
*   **ALB (Application Load Balancer):** Балансировщик нагрузки, терминирующий HTTPS (используется ACM сертификат) и перенаправляющий трафик на ECS.
*   **Security Groups:** Строгое разграничение доступа (ALB -> ECS -> RDS).
*   **Secrets Manager:** Безопасное хранение паролей БД, токенов GitHub и ключей Auth0. Пароли не передаются в открытом виде.
*   **IAM Roles:** Принцип наименьших привилегий для ECS Task и Lambda Execution ролей.

## Технические решения и особенности

### 1. Инициализация базы данных (Lambda + Custom Resource)
Для автоматического создания пользователя приложения (`app_user`) и выдачи ему прав (`GRANT ALL`) используется Lambda-функция `CreateDBUserFunction`.

**История проблем и их решения:**
*   **Проблема 1 (Lambda в VPC без интернета):** Изначально Lambda была настроена внутри VPC, но без NAT Gateway или VPC Endpoint'ов, что не давало ей доступа к AWS Secrets Manager и CloudFormation API.
    *   **Решение:** Удалена секция `VpcConfig` из настроек Lambda, что позволило ей запускаться вне VPC и иметь полный доступ в интернет.
*   **Проблема 2 (Драйвер psycopg2):** Лямбда падала с ошибкой `ImportError: libpq library not found` при использовании `psycopg2` (даже через Klayers). Это связано с отсутствием необходимых бинарных зависимостей (`libpq`) в среде Lambda.
    *   **Попытка решения:** Сначала была попытка использовать слой `AWSSDKPandas`, который, как предполагалось, содержит `psycopg2`. Однако `psycopg2` был удален из `AWSSDKPandas` из-за проблем с размером и платформой. Также была попытка использовать слой `Klayers-p311-psycopg` (Psycopg 3), но он также не содержал необходимых бинарников `libpq` и приводил к ошибкам.
    *   **Финальное решение (pg8000):** Переход на драйвер **`pg8000.native`**. Это **Pure Python** драйвер, который не требует компиляции и внешних библиотек (`libpq`), что делает его идеально подходящим для AWS Lambda. Библиотека `pg8000` доступна через официальный слой AWS: **`AWSSDKPandas-Python311`**.
    *   ARN слоя: `arn:aws:lambda:us-east-1:336392948345:layer:AWSSDKPandas-Python311:24`.

### 2. Проблемы с удалением стека CloudFormation
Многократные попытки удаления стека (`dfm-dev`) приводили к зависаниям (`DELETE_IN_PROGRESS`, `ROLLBACK_FAILED`, `DELETE_FAILED`) из-за следующих ресурсов:
*   **`AttachGateway`:** Зависал, если в VPC оставались активные сетевые интерфейсы (ENI).
*   **`CreateDBUser`:** Custom Resource, который висел в ожидании ответа от Lambda.
*   **ENI от Lambda:** Оставались активными после неудачного запуска или удаления Lambda, блокируя удаление подсетей и VPC.
*   **RDS Instance:** Иногда оставался "жить", блокируя удаление VPC.

**Методы решения проблем с удалением:**
*   **Диагностика:** Использование `aws cloudformation describe-stack-events` и `aws ec2 describe-network-interfaces` для выявления зависших ресурсов.
*   **Ручное вмешательство:**
    *   Удаление зависших RDS инстансов (`aws rds delete-db-instance --skip-final-snapshot`).
    *   Удаление зависших Lambda функций (`aws lambda delete-function`).
    *   Ручное отсоединение/удаление Internet Gateway (`aws ec2 detach-internet-gateway`, `aws ec2 delete-internet-gateway`).
    *   Принудительное удаление стека с опцией `--retain-resources` для ресурсов, которые блокируют удаление (например, `AttachGateway`, `VPC`, `CreateDBUser`).
    *   *Примечание:* В конечном итоге стек был удален полностью после ручной зачистки Lambda функции.

### 3. Сетевой доступ Лямбды (Dev Mode)
В Dev-окружении база данных доступна публично (`PubliclyAccessible: true`).
Для экономии (отказ от NAT Gateway) Lambda-функция инициализации настроена **БЕЗ привязки к VPC**.
*   Это дает ей прямой доступ в Интернет (для общения с AWS Secrets Manager и CloudFormation).
*   Она подключается к RDS через его публичный DNS-адрес.

## Инструкции по развертыванию

### Предварительные требования
*   AWS CLI настроен и аутентифицирован.
*   Файл параметров `parameters-dev.json` заполнен актуальными секретами.

### Скрипт deploy.sh

Универсальный скрипт для управления CloudFormation стеком.

#### Команды

| Команда | Описание |
|---------|----------|
| `./deploy.sh create` | Создать новый стек |
| `./deploy.sh update` | Обновить стек через Change Set (с превью изменений) |
| `./deploy.sh delete` | Удалить стек |
| `./deploy.sh deploy` | **Принудительный редеплой ECS** — перезапускает таски с новым образом |
| `./deploy.sh status` | Показать статус стека и ресурсов |
| `./deploy.sh outputs` | Показать выходные параметры стека (URLs, endpoints) |
| `./deploy.sh events` | Показать последние 20 событий стека |
| `./deploy.sh logs [min]` | Показать логи ECS (по умолчанию за 10 минут) |
| `./deploy.sh rollback` | Отменить текущее обновление и откатиться |
| `./deploy.sh help` | Показать справку |

#### Типичные сценарии использования

**Первый деплой:**
```bash
./deploy.sh create
```

**Обновление инфраструктуры (изменения в template.yaml):**
```bash
./deploy.sh update
```
Скрипт покажет список изменений и применит их.

**Обновление Docker-образа (без изменений в CloudFormation):**
```bash
./deploy.sh deploy
```
Заставляет ECS запустить новые таски с последним образом из ECR/GHCR.

**Диагностика проблем:**
```bash
./deploy.sh events    # посмотреть что пошло не так
./deploy.sh logs 30   # логи приложения за последние 30 минут
```
