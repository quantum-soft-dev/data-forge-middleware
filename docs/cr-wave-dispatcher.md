# CR: `/wave` — диспетчер волны, перенесённый из zmanly

Дата: 2026-09-25. Статус: реализовано. Issue: #358.

## Зачем

`/github-issue-runner` держит до трёх задач в работе, но всё, что он решает, — прозой: какие задачи
взять, какие не ставить рядом, сколько слотов свободно, где карточка должна стоять. В проекте zmanly тот
же процесс прошёл несколько волн и вырос в команду `/wave`, где арифметика — в скрипте с журналом, а
процессы, которые молча зависают, ловит почасовая проверка. Этот CR переносит её сюда и приводит к правилам
этого репозитория.

## Что появилось

| Файл | Роль |
|---|---|
| `.claude/commands/wave.md` | координатор: расчёт → взятие → запуск исполнителей → ревью → merge по одному → добор → сверка → отчёт; `resume`, `health` |
| `.claude/agents/task-runner.md` | исполнитель одной задачи в готовом worktree; доску своей задачи не трогает; ответ — блок `WAVE-RESULT` |
| `scripts/wave.sh` | `plan`, `refill`, `begin`, `add`, `mark`, `status`, `verify`, `end`, `budget`, `health` |
| `scripts/board.sh` | новые `items`, `field <n> Size`, `sweep [--fix]` |

`/github-issue-runner` остаётся для режима A (задачи в видимых workspace'ах Conductor). Автономный прогон
субагентами — `/wave`; одновременно две команды не запускаются.

## Что изменено против zmanly — и почему

| zmanly | здесь | почему |
|---|---|---|
| волна до 4 | до **3** | в `CLAUDE.md` три — жёсткий потолок диспетчера: три ревью и три очереди CI |
| пул — `Ready` с майлстоуном | `Backlog` + `Ready`, любой майлстоун | правило пула этого репозитория; спринтовые майлстоуны пусты |
| Priority — поле доски, строка `Priority:` в теле | метка `priority: high/medium/low` | поле `Priority` доски 16 не single-select; приоритет здесь живёт в метке |
| ключи пересечения — метки `mod:*`/`area:*` | имена файлов из «Что тронет» + `flyway`, `specs`, `proto`, `stand` | меток модулей нет; раздел «Что тронет» обязателен в формах (#216) и называет ровно три невидимые git коллизии |
| тикет без меток — ключ `area:*` | тикет без «Что тронет» — `files?` | два таких не идут в одну волну; координатор проверяет grep-ом, молчание — не «пересечений нет» |
| база всегда `develop` | `scripts/issue-base.sh` по телу | тикеты миграции (#298); отказ скрипта — задача не берётся; после merge в `migration/*` тикет закрывается явно |
| `gh pr merge --squash --delete-branch` | `scripts/pr-merge.sh` | #332: из worktree gh падает на локальной уборке после merge |
| ревьюеры correctness/tenancy/architecture | correctness/contracts/architecture | линзы этого репозитория; плюс проверка `reviewThreads`/`PENDING`/`CHANGES_REQUESTED` |
| — | ребейз перенумеровывает Flyway-миграцию | номер миграции — одно пространство на все ветки; git конфликта не видит |
| метки `status:*` 1:1 с колонками | `status: ready to merge` = колонка `In Review` | «Ready To Merge» здесь метка, а не колонка; `sweep` и `verify` это знают |

## Правила, пришедшие вместе с волной

- **Бюджет GraphQL** читается `scripts/wave.sh budget` (запрос `rateLimit` самого GraphQL, 1 очко).
  Прежнее правило советовало `gh api rate_limit`, а он для GraphQL показывает `used: 0`, когда очки уже
  списаны (замерено в zmanly). Порог старта волны — 1000 очков, merge — 200.
- **Метки `status:*` — только через `board.sh`.** Прямая правка метки двигает метку без колонки; отказ
  `board.sh` — стоп, а не обход.
- **Назначение — до перехода, сверка колонки — после.** Автоматизация доски 16 реагирует на события
  (`Pull request linked to issue`, `Item added to project`) и может перебить переход.
- **Блокировка — три случая**: открытый `Blocked by` — стоп; ручная метка без `Blocked by` — вопрос человеку;
  все блокеры закрыты, а метка висит — `board.sh unblock`.
- **Остановка возвращает статус**: `Blocked` или `Ready` до отчёта; `In Progress` без исполнителя врёт доске.
- **`board.sh sweep`** — сплошная сверка: `STALE_BLOCK`, `MANUAL_BLOCK`, `COLUMN`, `ABANDONED`, `CLOSED`;
  `--fix` чинит однозначное, перечитав тикет перед каждой правкой.
- **Здоровье волны**: координатор ставит `CronCreate` раз в час с `/wave health`; исполнитель не оставляет
  фоновых процессов и ждёт CI одной командой `gh pr checks <pr> --watch --interval 60`.

## Проверка

`BoardScriptTest` (items, field и его отказы, sweep с `--fix` и без) и `WaveScriptTest` (пул и порядок,
пересечения по файлу, `flyway` и `stand`, ключи задач в работе, `files?`, отказ базы, потолок, порог бюджета,
журнал и слоты, verify) — против stand-in `gh`, без сети. Мутации: убрать ключ `flyway` — краснеют два
случая волны; сопоставить `ready to merge` другой колонке — краснеет случай sweep.
